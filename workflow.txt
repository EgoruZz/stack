0. Make sure you are on up-to-date main
git checkout main
git pull origin main

1. Create a working branch
git checkout -b working

2. Work with files
(writing notes, code, diagrams)

3. Review the changes (very important)
git status
git diff

4. Add files (deliberately)
Option A: git add path/to/file1 path/to/file2
Option B: git add -p (interactive — better for growth)

5. Create a commit
git commit -m "type(scope): short description"
rule: 1 commit = 1 meaningful block of changes

6. Check the history (mandatory)
git log --oneline -n 5

7. Sync with main (BEFORE PUSH)
git fetch origin
git rebase origin/main

8. Push the branch to GitHub
git push origin working

9. Create a Pull Request (gh is available)
* base: main
* compare: working

10. PR description (mandatory)
## What was added
- ...

## Why
- ...

## Notes
- ...

11. Review (mandatory)
Before merge, check:
* no junk
* changes split logically
* no extra files

12. Merge via GitHub (gh is available)
Click: "Merge pull request"
Choose: "Create a merge commit"

13. Switch to another branch
git checkout main
git pull origin main

14. Delete the branch (optional)
git branch -d working
git push origin --delete working

15. Release (OPTIONAL — not on every commit/PR, but when you decide yourself)
Release = a tag + notes on the repository's Releases page (GitHub).
Stack users see: what's new and whether a re-run of setup.sh is needed.
Command:
git tag vX.Y.Z && git push origin vX.Y.Z
gh release create vX.Y.Z --title "vX.Y.Z" --notes "- changes...
Re-run setup.sh: yes/no (bash ~/stack/setup.sh — idempotent)"
Rule: patch (X.Y.+1) — a regular update-all.sh; minor/major (X.+1.Y,
+1.0.0) — after update-all.sh run setup.sh, then restart OpenCode.
